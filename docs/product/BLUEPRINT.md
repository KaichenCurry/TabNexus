## 1. 定位一页纸

**一句话**：TabNexus 是浏览器与 Agent 之间的任务上下文层——把 50 个 Tab 变成一份人和 AI 都能继续编辑的任务文档。

**双层结构（用户拍板：基础 Tab 管理是日常底座，永不可丢）**：

| 层 | 定位 | 场景 |
|---|---|---|
| **底座：日常 Tab 管理** | 保存 / 恢复 / 删除 / 关闭，不建任务、不配 AI 也能用 | 每天的高频动作 |
| **升级：任务上下文** | 任务文档 + 画布 + 进度条 + Agent | 跨天任务、需要产出 |

> **第一原则：底座永远可用。** 任何重构都不能让"保存一个页面、找回一个页面"依赖建任务或依赖 AI。底座做得好，用户才会留下来；任务层做得好，用户才会回来。

**三大问题**（唯一口径，勿再改）：

| # | 问题 | 用户原话 | 本质 |
|---|---|---|---|
| P1 | **记不住** | "第二天回来，网页还在，思路断了" | Tab 只存 URL，不存"为什么" |
| P2 | **传不走** | "要写结论/交给 AI，只能一个个复制链接重新解释" | 人肉 API |
| P3 | **收不拢** | "存进去了，然后就没有然后了" | 保存即遗忘，无交付物 |

**vs Browser Use / Computer Use**：他们读 live tabs 的快照（每次重扫、贵、慢、隐私暴露）；TabNexus 存跨会话的、带人类判断的任务档案——**上下游关系，非竞品**。档案给现场扫描当地图，把"盲扫 50 页"变成"精读 2 页"。

**目标用户**：以任务为单位开 10–50 个页面、任务跨天、最终要交给 AI/Agent 的知识工作者。

**DSH v0.3 边界**：DSH 本身已经是 Agent，TabNexus 不重复建设 Agent 接入层。DSH 版只在官方 `shell.overlay` Slot 中提供任务、分类、网页资料与三段式流程界面，数据保存在 Web Client 的 `localStorage`；只接受 `http://` / `https://`。Chrome 版的 MCP/Agent 能力与 DSH 版解耦。

## 2. 产品范式：底座 × 任务文档 × 画布 × 进度条

> **Tab 是入口，Page 是文件，Task 是文档，画布是思路，进度条是仪表盘，Agent 是协作者，底座是日常。**

| 支柱 | 形态 | 解决 |
|---|---|---|
| **日常底座**（Popup / Inbox / ⌘K） | 保存 / 恢复 / 删除 / 关闭，零 AI 依赖（§3.3） | 每天的高频动作 |
| **任务文档**（默认主界面） | 任务头 + 自由章节 + Page 引用块 + 结论区 | P1、P3 |
| **Excalidraw 画布**（平行视图） | 手绘风节点/箭头，AI 可编辑样式与关系 | P1（关系记忆） |
| **分段进度条**（任务头内嵌） | 章节段 ∝ 页数、填充 ∝ 阅读进度、⭐已采用 | P2（进度可传）、P3（交付感） |

**渐进式呈现铁律**（沿用审计结论）：界面复杂度 ∝ 用户已投入的内容量。空任务只有「这次你想搞清楚什么？」输入框 + 收件口；有内容才出现 AI 一键整理/总结/画布/交付。首屏可见操作 ≤ 7 个，空状态主 CTA 恒为 1 个。

## 3. 信息架构（全部界面就这五块）

### 3.1 工具栏 Popup（新，快速收集）

```
┌────────────────────────┐
│ TabNexus               │
│ 当前页  GitHub·DSH     │
│ 保存到 [最近任务 ▾]     │
│ [保存当前页] [选择窗口页面]│
│ ────────────────────── │
│ 打开任务文档            │
└────────────────────────┘
```

目标：保存当前页 ≤ 2 次点击。收集是高频动作，必须独立于全页。

### 3.2 全页：双视图 + 一个 Drawer

```
┌────────┬───────────────────────────────────────────────┐
│ 任务    │ [文档] [画布]            ⋯         [让 Agent 继续]│
│        │ 🎯 评估 Perplexity 值不值得对标                  │
│ ● 竞品 │ ▓▓▓▓▓▓▓▓░░ 12/18 · ⭐3 · ● Codex                │
│   调研  │ 下一步：补一个失败案例                            │
│        │ ────────────────────────────────────────────── │
│ ○ Bug  │ 市场与商业模式                                   │
│   排查  │ ▎已采用 融资轮次     ↗  "估值90亿未披露ARR"      │
│        │ ▎已读   AI搜索市场规模 ↗                          │
│ ＋新任务│ 风险与反例                                       │
│        │ ▎已排除 2023测评  ↗  "已过期，不能用于当前判断"    │
│ ⚙ 设置 │ 当前结论                                        │
│        │ Perplexity 值得研究，但短期不宜复制…… [AI 总结]   │
│        │                              ┌──────────┐      │
│        │                              │ 收件口 6  │      │
│        │                              │  ☐ GitHub │      │
│        │                              │ [收进任务]│      │
└────────┴───────────────────────────────────────────────┘
```

- **左栏**：任务列表 + 新任务 + 设置。只有任务和设置，没有别的。
- **视图切换**：`[文档] [画布]` 两个纯文字 Tab，文档为默认。
- **任务头**：标题（可编辑）/ 进度条 / 下一步 + 主 CTA「让 Agent 继续」+ ⋯ 菜单（归档/导出/删除等低频操作）。
- **文档正文**：自由章节 + Page 引用块 + 结论区（固定尾部）。
- **Inbox Drawer**（临时抽屉，非常驻第三列）：只做"把当前窗口页面收进任务"一件事，主按钮「收进任务 N」；已保存折叠为一行；保存并关闭放进下拉。
- **⌘K 命令面板**：搜索任务/Page、建章节、标记状态、AI 一键整理、总结、导出、归档——低频能力全部收进来，不占界面。

**砍掉清单**：分组看板、xyflow 关系图、常驻筛选栏、右侧 6 按钮操作台、空状态插画、"分组空间已准备好"、教程轮播、语言切换（进设置页）、"已自动保存"常驻（改瞬时 toast）。

### 3.3 日常底座：基础 Tab 管理（不建任务、不配 AI 也能用）

| 动作 | 入口 | 规格 |
|---|---|---|
| 保存当前页 | Popup | ≤ 2 次点击，默认进最近任务，无任务则自动开一个 |
| 保存整个窗口 | Popup / Inbox | 一键全选当前窗口（固定标签默认跳过，可手动加） |
| 保存并关闭 | Inbox 下拉 | 先持久化后关闭，固定标签永不批量关闭 |
| 恢复 / 重开 | ⌘K / 文档 / Popup | 恢复单页、单章节或整个任务；已打开的 URL 自动去重跳转 |
| 删除 | ⋯ 菜单 / ⌘K | 删卡片、删任务；破坏性操作带确认 |
| 最近关闭缓冲 | Popup / Inbox 折叠区 | 未保存就关掉的页面可找回；支持恢复与移除 |
| 去重 | 引擎自动 | 同 URL 不重复入库（沿用现有 normalizeUrl） |

**底座原则**：

1. 所有底座动作**零 AI 依赖、零建任务依赖**——它们是"工具"，不是"工作流"；
2. 底座 UI 只在 Popup / Inbox / ⌘K 出现，不占文档主界面；
3. 引擎完全复用现有实现（采集/去重/固定标签保护/最近关闭缓冲/恢复），R1 只换入口外壳；
4. file:// 与权限提示沿用现有交互（需授权时明确提示，不静默失败）。

## 4. 任务链 v2（全新运行逻辑）

| # | 动词 | 行为 | 载体 |
|---|---|---|---|
| 1 | **立** | 首启只问一句「这次你想搞清楚什么？」→ 建任务 | 空状态输入框 |
| 2 | **收** | Popup 收单页 / Inbox 批量收窗口页 → 「收进任务」 | 收件口 |
| 3 | **整** | 「✦ AI 一键整理」选模式（内容/时间/域名/自定义）→ AI 出可编辑预览 → 确认 | 文档正文（§6） |
| 4 | **读** | 在引用块上勾状态（未读/已读/已采用/已排除）、写备注（正面显示） | Page 引用块 |
| 5 | **结** | 「AI 总结」写结论区 / 自己写 / 「让 Agent 继续」代写 → 进度条涨满 → 完成任务归档 | 结论区 + 进度条 |

保存动作只持久化，**绝不自动建章节/按域名分组**（AI 一键整理永远是用户显式动作）。

## 5. 数据模型 v2（Schema v2）

```ts
type Task = {
  id: string;
  name: string;              // 任务名（= 首启问题的答案）
  goal: string;              // 一句话目标（人写 / AI 建议）
  nextStep: string;          // 下一步（人 / AI / Agent 写）
  conclusion: string;        // 当前结论（人 / AI / Agent 写）
  summary?: string;          // AI 一键总结缓存
  sections: Section[];       // 自由章节，有序、可折叠
  pages: Record<string, Page>;
  canvas: CanvasState;       // Excalidraw elements JSON + appState（gzip 压缩存）
  archivedAt?: string;
  createdAt: string;
  updatedAt: string;
  // progress 为派生值：由 pages.status 聚合计算，永不落库
};

type Section = { id: string; name: string; color?: string; pageIds: string[]; collapsed?: boolean };
type Page = {
  id: string; title: string; url?: string; note: string;
  status: "unread" | "read" | "adopted" | "excluded";  // 新增 excluded
  excludedReason?: string;                              // 新增：排除原因（P1 的"为什么不要"）
  source: "user" | "ai" | "agent"; savedAt?: string;
  canvasNodeId?: string;   // 画布节点绑定
};
```

**迁移（v1 → v2，纯函数、可回滚）**：`Group→Section` 1:1；`Card→Page` 1:1（status 兼容映射）；`edges→canvas arrows`；`Workspace.name→Task.name`。**MCP 17 工具名不变**，输入输出在适配层做 v1↔v2 映射——旧 Agent 客户端零破坏。画布新增 3 个工具（§8.4），MCP 总数 20。

## 6. AI 一键整理与一键总结（D2 落地）

入口：文档顶部"未归类"区旁的 `[✦ AI 一键整理]` 按钮（只有存在未归类 Page 时才亮）。

| 模式 | 行为 | 依赖 |
|---|---|---|
| 按内容理解 | AI 语义分组 + 逐条归类理由 | 模型 API |
| 按时间 | 今天 / 本周 / 更早 | 无 |
| 按域名 | 域名聚合（**用户主动选择**，绝非默认） | 无 |
| 自定义提示词 | 如"按背景、证据、反例、结论" | 模型 API |

- 每次 AI 一键整理 = 一次全新分组建议 → **可编辑 Diff 预览 → 用户确认应用**；不强制任何固定结构；可撤销。
- **一键总结**：对任务全部 Page（仅标题/URL/备注/状态，**不发正文**）生成结构化摘要 → 写入结论区，可继续人工编辑。
- 未配置 AI：按时间/按域名照常可用；按内容/自定义引导去设置配置，不伪装不欺骗。

## 7. 分段式任务进度条（D3 落地）

任务头第二行，GitHub milestone 风格：

```
▓▓▓▓▓▓▓▓▓░░░  12/18 已读 · ⭐ 3 已采用
└─市场与商业模式─┘└─风险与反例─┘└─未归类─┘
```

- **一段 = 一个章节**：段宽 ∝ 章节 Page 数；段色 = 章节色（受限调色板）；
- **段内填充 = 章节阅读进度**：未读 0% / 已读 50% / 已采用 100%，按 Page 加权；已排除不计入分母、单独灰显；
- **段可点击** → 滚动定位到该章节；
- 右侧常显 `已读/总数 · ⭐已采用`；
- **可交付态**：全部已读且 ≥1 已采用 → 进度条高亮，「让 Agent 继续」「AI 总结」随之高亮；
- **结论区**：文档尾部固定区块 = "当前结论"文本 + 「AI 总结」按钮；写入结论 = 完成度 +1 ⭐，与进度条双向联动；
- 进度条是纯派生组件（`taskModel.ts` 一个纯函数 `computeProgress(task)` 产出），无状态同步负担。

## 8. Excalidraw 画布（D1 落地）

### 8.1 选型事实（已核验，非猜测）

| 项 | 事实 |
|---|---|
| 包 | `@excalidraw/excalidraw` **v0.18.1**，**MIT** |
| 兼容 | peerDeps 支持 **React 19** ✅（项目 React 19.2.7） |
| 加载 | **`React.lazy` 动态 import**，仅首次打开画布时下载，不影响扩展冷启动 |
| 数据 | `elements: ExcalidrawElement[]`（rectangle/text/arrow/freedraw…，含坐标/描边色/填充/roughness）+ `appState` + `files`——**纯 JSON，AI 天然可编辑** |
| 已知坑 | [issue #7585](https://github.com/excalidraw/excalidraw/issues/7585)：`updateScene()` 与 `initialData` 覆盖时序——**R3 POC 第一天验证**，固化正确用法（受控 data 或正确调用顺序） |

### 8.2 画布 ↔ 文档同步协议

| 任务数据 | 画布元素 |
|---|---|
| Page | 手绘风节点（章节色描边 + 状态角标：⭐已采用 / 半填充已读 / 空心待读 / ✕已排除） |
| 关系 edge | 手绘箭头（边上 label 文本） |
| 章节 | 低透明度容器框 + 名称 text |
| Page.canvasNodeId | 元素 id 绑定（同步依据） |

- 打开画布：按文档现状**生成/增量同步**元素（卡片增删 → 元素增删；状态变化 → 角标变化）；用户在画布的增删改 → onChange 写回；
- 画布故障不影响文档闭环（画布是一级视图，但文档是主路径）。

### 8.3 AI 编辑画布（三层，全部"JSON 变更 → 校验 → 预览 → 应用 → 可撤销"）

| 层 | 触发 | 能力 |
|---|---|---|
| 人 | 画布上手绘/拖拽/连线 | Excalidraw 原生 |
| 内置 AI API | 画布工具栏「✨ 整理画布」+ 意图（"按证据链从左到右排""给结论节点换红色"） | LLM 输出画布变更 JSON：移动/改样式/增删箭头/重排 |
| Agent | MCP 画布工具 | §8.4 |

**变更校验器（`canvasSync.ts`，必做）**：只允许引用存在的 Page id；坐标/尺寸限幅；颜色限调色板；每次变更记 revision + 活动留痕。

### 8.4 MCP 扩展：17 → 20 工具

| 新工具 | 作用 |
|---|---|
| `read_canvas` | 读画布 JSON（元素/边/样式/位置摘要） |
| `propose_canvas` | Agent 建议画布变更（走 Agent 活动审查流，用户确认后应用） |
| `edit_canvas` | 携带 expectedRevision 直接编辑（版本校验 + 幂等收据，同 `edit_workspace`） |

### 8.5 存储与权限

- 画布 JSON 用 pako（包自带依赖）gzip 压缩后写 `chrome.storage.local`；
- manifest 增补 `unlimitedStorage` 权限，商店审核如实披露用途（"存储本地任务画布"）。

## 10. 实施路线（每期独立可验收）

## 11. DSH 双形态战略（v0.3 执行基线）

- **独立仓库**：DSH 插件在 [`KaichenCurry/TabNexus-DSH`](https://github.com/KaichenCurry/TabNexus-DSH) 独立开发与发布，不修改 Chrome 扩展运行代码。
- **只做简单功能**：任务创建/切换/设置，分类整理，网页标题/URL/备注，以及“待处理 → 进行中 → 已完成”的轻量流程视图。
- **纯 Client**：Host 为空壳；不注入 `tools` 或 `webServer`，不注册 `mcp__tabnexus__*`，不提供 `/plugins/tabnexus/*` 路由、SSE、Skill 或 Agent preset。
- **本地优先**：状态保存在 `tabnexus:dsh:workspace:v3` 浏览器本地存储；不需要账号、数据库、模型或 API Key。
- **原生入口**：使用官方 `shell.overlay` Slot；右上角胶囊打开玻璃 Dock，支持展开工作区和窄屏抽屉。
- **网页限定**：只接受 `http(s)`；规范化 URL、去追踪参数、同任务去重。不读取或关闭真实 Chrome 标签。
- **双形态关系**：Chrome 版继续承担浏览器采集与 Agent 桥接；DSH 版是 Agent 界面内的独立轻量任务管理器，首版不做数据同步。
- **口号**：**「一切皆插件 —— DSH 也可以有自己的 Tab 管理器。」**

## 12. 风险与红线

**风险**：① 画布吞噬主线（控制：画布非默认视图、独立阶段交付、AI 改动必预览）；② 自由章节失控（控制：可选模板+AI 建议，章节恒由用户编辑，支持快速合并/重命名）；③ Excalidraw 受控 API 坑（控制：R3 POC 第一天验证 issue #7585）；④ DSH 预览版 Slot 变动（控制：rc.6 基线、隔离 profile、真实 Web/桌面与响应式验收）；⑤ Schema v2 破坏旧数据（控制：纯函数迁移+备份+双读验证+回滚）。

**红线（任何阶段不得破坏）**：① 本地优先与隐私边界（不发正文/备注，Key 不暴露给 Agent）；② 破坏性操作确认 + revision/幂等收据；③ MCP 工具名与契约（新增只做加法）；④ 中英双语 + `pnpm check` 全量回归（189 测试与 E2E 同步更新文案断言）。

## 13. 验收场景（必过）

- **A 首启**：20 个调研 Tab → 输入"评估某产品是否值得对标" → 选 12 页 → 60 秒内得到可编辑任务文档；全程不见看板/关系图/域名分组/教程轮播。
- **B 续作**：次日打开任务，立即看到目标、下一步、进度条、未读/采用/排除；不自动重开 Tab。
- **C AI 一键整理**：「✦ AI 一键整理」按内容/时间/域名/自定义 → 可编辑预览 → 确认应用；「AI 总结」写入结论区。
- **D Agent 接手**：「让 Agent 继续」→ 预览上下文范围（目标/章节/18 Page/备注/状态/排除原因/下一步；不含正文与 Key）→ DSH 写回结论与 Artifact，留痕可撤销。
- **E 完成归档**：确认结论 → 可选关相关 Tab（固定标签除外）→ Markdown/JSON 含目标/结论/下一步/排除原因 → 任务归档可恢复。
- **F 画布**：切「画布」节点与 Page 同步、手绘持久化；「✨ 整理画布」AI 变更预览→应用→撤销；Agent `propose_canvas` 经活动审查确认。
- **G 旧用户升级**：v1 数据完整迁移；旧 MCP 客户端仍可读写；可回滚备份。
- **H 日常底座**：不建任务、不配 AI 的前提下——Popup 保存当前页 ≤2 点击；一键保存整个窗口（固定标签跳过）；保存并关闭（固定标签不动）；从最近关闭恢复一个页面；删除一条记录带确认；同 URL 保存自动去重。

## 14. 成功指标

- **北极星**：每周完成的上下文任务数（任务含目标 + ≥5 Page + 结论，并标记完成）。
- P1 记不住 → 创建后 7 日仍被打开的任务比例 ≥ 40%；
- P2 传不走 → 点击「让 Agent 继续」到 Agent 拿到完整 Context Packet ≤ 10 秒；
- P3 收不拢 → 活跃任务最终写结论并完成的比例 ≥ 30%；
- 体验线：首启→第一份文档 ≤60 秒；单页保存 ≤2 点击；20 Tab 批量收集 ≤3 动作；首屏操作 ≤7；空状态 CTA =1。

## 15. 一句话总结

> 旧 TabNexus 是一套功能过剩、表达混乱的标签管理器；
> 新 TabNexus 是一个**任务文档 + 一块 AI 能画的 Excalidraw 白板 + 一条看得见的进度**——引擎不动，外壳与逻辑全部重做。
> **Tab 是入口，Page 是文件，Task 是文档，Agent 是协作者。**
