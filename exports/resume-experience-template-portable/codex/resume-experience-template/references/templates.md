## 1. 最小信息收集模板

材料足够时不要机械追问。材料过少或关键结果缺失时，从下列问题中选择最多 3–5 个最能提高质量的问题：

```text
目标岗位/JD：

公司/组织、部门、岗位、时间、地点：
这段经历主要解决什么业务问题或目标：
你本人具体负责什么，哪些是团队成果：
你采取了哪些关键动作/方法：
实际使用了哪些工具、功能和使用程度：
交付了什么，谁使用或采纳了：
产生了什么结果，数据口径和时间周期是什么：
有无改版前、目标值、同期或同行等对标：
这段经历中最能在面试展开的一件事：
```

优先追问“采用情况、个人贡献、结果口径”，因为它们最能区分普通职责和真实价值。

## 2. 完整简历结构模板

个人信息、教育信息、工作/实习经历为必备模块。建议篇幅占比：个人信息 8%–10%，教育信息 10%–15%，工作/实习经历约 70%，技能、荣誉或其他约 10%。兴趣爱好和个人评价非必需，证据不足的主观评价直接省略。

版式要求：

- 按时间由近到远排列；

- 同级标题使用相同字号和字体；
- 经历之间适度留白，板块边界清楚；
- 一级为公司/学校，二级为岗位/专业，三级为具体内容；
- 不同经历减少重复能力证明，让面试官一眼看出差异。

## 3. 工作/实习经历模板

### 最稳版

适用于结果信息不完整但动作和交付可信的情况：

```markdown
公司名称｜部门｜岗位｜时间｜地点
一句话职责概括：负责【范围】，围绕【业务目标】开展【核心工作】。
- 【能力一】负责【问题/目标】，采用【方法/具体动作】，形成【交付/已确认结果】。
- 【能力二】针对【问题】，使用【工具具体功能】处理【对象/规模】，产出【交付】，用于【已确认使用场景】。
- 【能力三】识别/优化【对象】，通过【验证或推进方式】，实现【已确认的效率、质量、采用或结果】。
```

### 高竞争力版

仅在采用、对标、所有权和商业结果有证据时使用：

```markdown
公司名称｜部门｜岗位｜时间｜地点
一句话职责概括：负责【业务范围】，聚焦【关键问题】并支持【决策/增长/效率/风险目标】。
- 主导/负责【关键问题】，通过【方法】，识别【结论】，推动【采用/落地】，带来【结果及口径】。
- 搭建/优化【模型/流程/机制】，覆盖【规模】，使【指标】由【基线】变为【结果】，用于【业务场景】。
- 产出【方案/分析】，获得【角色/团队】采纳并应用于【决策】，贡献于【可解释的商业结果】。
```

若现有证据不足以支持高竞争力版，只说明需要补充的事实，不输出带有虚构占位数字的“成稿”。

## 4. 项目经历模板

```markdown
### 项目名称

- 【能力模块】有力动词 + 具体动作/方法 + 已验证结果。
- 【能力模块】有力动词 + 具体动作/方法 + 已验证结果。
- 【能力模块】有力动词 + 具体动作/方法 + 已验证结果。
- 【能力模块】有力动词 + 具体动作/方法 + 已验证结果。（可选）
- 【能力模块】有力动词 + 具体动作/方法 + 已验证结果。（可选）
```

项目描述按能力拆分，例如研究/分析、方案/设计、验证/落地、结果/复盘；不要按“第一周做什么、第二周做什么”写流水账。

## 5. 技能模板

错误：

```text
熟练掌握 Excel、SQL、Python，沟通能力强。
```

结构：

```text
工具：可【独立/在指导下】使用【具体功能】处理【对象/规模】，用于【实际场景或交付】。
```

只有事实支持时，才能写具体功能和程度。例如“能独立编写多表连接与聚合查询，用于周度经营数据提取”，比“熟练 SQL”更可验证。

## 6. 默认交付格式

```markdown
## 推荐定位

最稳方向：【方向及原因】。
最有竞争力方向：【方向及证据条件】。（仅在存在显著差异时）

## 可直接使用版

【公司/项目、职责概括、Bullet Point 成稿】

## 待补充增强点

- 【可显著提高结果层级的具体问题】
- 【需要核实的数据口径/采用情况/个人贡献】
```

若用户只要求最终文案，可省略推荐定位和增强点，直接交付干净成稿。若用户要求多段经历，先按时间倒序排列，再统一能力模块和措辞。

## 7. 审阅输出模板

```markdown
## 核心判断

【一句话说明当前简历最强证据和最大问题】

## 必须修改

- 原文：【原 Bullet】
  问题：【事实/逻辑/结果/表达问题】
  改写：【有事实支撑的版本】

## 可直接使用版

【统一排版后的完整成稿】

## 需要补证

- 【数字、对标、采用、商业结果或个人责任边界】
```

审阅时优先指出会导致面试追问失守、事实夸大或核心能力不清的问题；不要把个人审美偏好包装成硬性规则。
